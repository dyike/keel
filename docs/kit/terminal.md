# Terminal

English | [简体中文](terminal.zh-CN.md)

Terminal() is a pure-Go ANSI display with application-owned input/output. It never starts a shell, opens a network connection or performs OSC clipboard operations. Connect OnData(func(string)) to your process, PTY, WebSocket or SSH transport, and pass received bytes to Write. WriteString is also available; both implement the usual writer return values. Calls from background work must be made inside core.Update or core.UpdateIf, like other Keel views. Output is accepted while input is disabled and never triggers OnData.

Name labels the textbox. Height sets its nested viewport height (default 320dp); Fill uses the available space. An el.Root can fill the window. Size reports character columns/rows; OnResize reports a changed size after actual visible layout, not measurement. The first visible layout also reports its size. Dimensions are bounded to 512 columns and 256 rows. Resizing preserves/clamps the current screen but does not reflow old text. Scrollback sets retained history lines, from 0 to 10000, default 1000. Reset clears screen, history, parser modes and selection without sending input. Text returns plain screen/history text, including blank screen rows.

ANSI support includes 16/256/RGB colors, bold, dim, italic, underline, inverse and strike; carriage return, line feed, backspace, tabs, delayed wrapping; cursor positioning/save/restore; erase screen/line/characters; insert/delete characters/lines; scroll regions; alternate screen 1049; cursor visibility, application cursor and bracketed paste modes. UTF-8 and escape sequences may be split across writes. Wide and combining/ZWJ text uses grapheme-aware cells. Screen history and parser buffers are bounded. Unsupported control strings are consumed, not executed. This is not full xterm/VT compatibility: mouse reporting, terminal queries, alternate character sets, colon-form SGR, advanced keyboard protocols and history reflow remain unsupported.

Input is sent without local echo; the application writes any echo. Committed text, Return, Backspace, Tab, Escape, Ctrl-letter combinations, arrows, Home/End, Delete, PageUp/PageDown and F1–F12 produce terminal sequences. Application cursor mode changes arrow sequences. Escape followed by Tab allows focus to leave; ordinary Tab is sent to the session. Pointer clicks/taps focus the terminal. IME composition is displayed locally and committed once when the composition ends; real-platform IME acceptance is separate from the event-harness tests.

Drag with a mouse to select. Ctrl+Shift+C (or Super+C) copies Selection; Ctrl+C always sends byte 3. Ctrl+Shift+V (or Super+V) requests clipboard text; bracketed paste wraps it when enabled. Clipboard input is limited to 1MiB. Copy uses displayed row boundaries and complete wide graphemes. Unrelated output preserves a selection; overwriting selected text or evicting selected history clears it. Wheel/touch scrolling can leave the bottom; incoming output retains the scrolled view, adjusting for evicted history. New keyboard input resumes following output. SetDisabled blocks interaction and cancels transient input/paste, while silent output methods remain available. Ancestor disabling is respected.

Only visible rows are drawn. ANSI backgrounds and font styles use the existing Gio/theme glyph renderer, including supported platform color emoji. The cursor is solid: an idle terminal does not schedule blink frames. Accessibility exposes visible text and disabled state using the existing textbox role. Font coverage, physical device IMEs, actual PTY applications and client memory/frame performance require separate acceptance.

The Gallery example is an in-process command demonstration (help, colors, progress, echo, clear), not an operating-system shell. Its progress command uses finite scheduled updates and Ctrl+C cancels them. Production transports, process lifecycle, backpressure and output scheduling belong to the application.

Validation: go test ./ui/kit ./ui/window -run TestTerminal; go run ./examples/components -section terminal.
